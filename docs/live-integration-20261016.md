## 排除的运行问题

用户重启 oMLX 后，模型目录接口与实际推理请求均恢复响应。

已有的模拟地面站进程处于暂停状态（进程状态 `T`），导致 HTTP 请求超时。恢复进程后，确认其仍加载旧版协议：要求 `PRE_PLAN` / `create_task`，不能接收当前代码的 `AGENT_OUTPUT` / `upload_task` 和起飞高度参数。将该进程重启为当前代码版本后，上传、执行与任务查询均通过。Agent 会话和已经创建的草稿保持不变，随后成功上传原草稿。

本次无需修改业务代码或放宽参数校验。

## 验证结果

| 场景 | 输入 / 核对内容 | 结果 |
|---|---|---|
| 缺参澄清 | “新增放飞前出任务，原地起飞” | 提问起飞高度；没有工具调用，没有创建任务 |
| 多轮补参 | “起飞高度六十米” | 结合前一轮创建高度 60 m 的原地起飞草稿 |
| 三阶段 | 继续“上传刚才创建的任务”“执行刚才上传的任务” | 同一任务按 `draft → uploaded → executing` 流转 |
| 浏览器语音 | 点击开始、录入合成语音、再次点击结束 | 自动上传 WAV；真实 ASR 转写后再提交真实 LLM，无需再次发送 |

| 消息关联 | `/api/voice` 与随后 `/api/text` | 后一个请求的文本等于真实转写，`ref_msg_id` 指向 ASR 输出编号 |
| 工具显示 | 创建、上传和执行 | 界面显示实际 `create_task`、`upload_task`、`execute_task` 和成功回执 |
| 结果一致性 | 界面、Agent 状态、地面站查询、保存文件 | 任务 ID、任务参数与执行状态一致；落盘 JSON 等于地面站的消息信封 |
| 页面刷新 | 刷新已执行任务的界面 | 恢复任务、70 m 参数及三条状态变化记录 |
| C 型编队 | 文字入口：高度 80 m、打开角度 120°、半径 150 m、东经 120.1° / 北纬 30.2° | 真实 LLM 完整解析；界面七项参数和初始变化记录核对通过 |
| U 型编队 | 文字入口：高度 90 m、长度 200 m、宽度 80 m、东经 121.5° / 北纬 31.2° | 真实 LLM 完整解析；界面七项参数和初始变化记录核对通过 |
