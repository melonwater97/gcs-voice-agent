# PX4 仿真语音助手实施计划

日期：2026-10-27；分支：`feat/qgc-px4-link`。

## 已确认的产品边界

- 单架多旋翼，通过 pymavlink 上传并执行 PX4 Mission，不采用 ROS2 Offboard 控制。
- 独立语音助手通过 QGC 数据桥读取选点、未上传草稿和版本；地图选点可以改变实际仿真起飞位置。
- 实际位置变更仅允许已落地且未解锁，显示新旧位置并经界面批准后调整仿真，随后重新检查环境与航线。
- 用户在 QGC 绘制或导入航线，助手可协助修改。每次修改产生新版本，原审查和批准失效。
- 基础审查明确坐标、高度基准、任务结构和场景限值；不验证障碍物、地形，不声明全面安全。
- 上传与解锁并启动任务分别由界面按钮批准。语音或模型输出不能批准操作。
- 正常结束返航并自动落地。异常告警、请求人工接管，保留 PX4 既有失效保护；不由 AI 临时发起额外处置。
- 实际落地、解除解锁后收集本次飞行日志，计算指标，生成 Markdown，再由 Pandoc 转为 DOCX。
- Pi 负责对话与规划，Skill 提供场景方法，应用状态机负责持久化、人工审批和循环；首版不引入 LangGraph。

## 实施阶段与验收

1. [x] 环境与现有实现检查：Windows 安装版 QGC；WSL `Ubuntu-22.04`、`/opt/uav-sim`；项目已有 `uav/server.py`、`mission.py` 和 UDP 桥。
2. [x] 场景配置：可编辑提示词、仿真专用 MCP/工具白名单、新会话隔离；保留原地面站场景与配置。
3. [x] 持久化状态机：草稿、审查、待批准、执行中、待人工接管、日志和报告状态；等待用户不占用录音或对话执行回合。
4. [x] 人工审批：绑定飞行器、场景、航线内容版本和前置条件；批准单次消费、过期失效；执行前再次核对。应用恢复不重放写操作。
5. [ ] QGC 数据桥：选点、草稿结构、版本、预览、修改冲突检查；提供真实 QGC 接入模块和契约，不使用机载任务冒充未上传草稿。
6. [ ] 仿真 MCP：复用 pymavlink 思路，单一遥测读取器；只读检查、上传/读回核对、批准后启动、确定性任务完成返航、落地确认、日志获取。所有有副作用测试仅使用隔离测试环境，实际环境写操作仍等待用户按钮批准。
7. [x] 报告：完整版本化 Markdown 模板、真实日志解析和缺失项标注、Pandoc DOCX 转换、下载；转换失败只重试报告阶段。
8. [x] Web 界面：场景选择、流程进度、航线和审查详情、批准/拒绝、异常和报告下载；接入对话及工具轨迹。
9. [ ] 验证：无批准不能写、模型不能回填 token 越权、修改/状态变化使批准失效、拒绝/过期/重启不执行、读回不一致阻断启动、飞行异常不擅自发控制、报告缺数据不编造，以及旧场景回归。
