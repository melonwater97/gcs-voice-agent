# 前缀缓存配置与测试

2026-10-14 在本机 M1 Max（24 核 GPU、64 GB 内存）上测试。服务为 oMLX 0.6.3rc2，模型为 Ornith-1.5-35B-A3B-MLX-6bit。沿用项目提示词、实际 MCP 工具 Schema、默认思考模式、temperature=0、max_tokens=2048。

## 配置与启动

`~/.omlx/settings.json` 已启用 `cache.enabled=true`，设置 `cache.hot_cache_max_size="2GB"`。其他缓存策略沿用原配置，GDN 状态精度保留 fp32。原始文件和合法的无缓存回退配置已分别备份到：

- `~/.omlx/settings.before-prefix-cache-20261014-094441.bak`
- `~/.omlx/settings.rollback-prefix-cache-20261014-094441.json`

原文件中的缓存开关为不完整的 `tr`，修改时已修正为合法 JSON。

仅开启缓存时仍未命中：该版本将 ArraysCache 混合模型的块尺寸提高到 2048 token；我们的输入总长约 1640 token，小于一个完整缓存块。

项目启动适配器 `scripts/serve_omlx_cached.py` 在服务进程内将 ArraysCache 模型的缓存块与 prefill 分块同时设为 512 token。它不修改第三方安装文件，并仅允许已验证的 oMLX 0.6.3rc2；升级后需重新验证。分块变化可能产生数值或生成文本差异，已核对本项目五类合法任务的实际参数，但这不等于通用模型质量评测。

从项目根目录运行：

```sh
/opt/homebrew/opt/omlx/libexec/bin/python scripts/serve_omlx_cached.py \
  --model-dir /Users/melonwater/project/OMLXProject/models --port 18000
```

需要上游默认分块时，停止适配服务后使用普通 `omlx serve ...`。若要完整回退缓存配置，在服务停止后用上面的合法回退文件恢复 `settings.json`。原始 `.bak` 因含不完整 JSON，不能直接作为运行配置。

## 同一口令对比

口令为“新增放飞前出任务，模式为原地起飞”。耗时使用服务返回的统计，不包含 Python/MCP 启动、ASR 和地面站 HTTP 执行。

| 配置 | 缓存命中 token | 首 token 等待 | 生成耗时 | 输出 token | 模型请求总耗时 |
|---|---:|---:|---:|---:|---:|
| 缓存关闭，稳定运行 | 0 | 4.23 s | 2.52 s | 137 | 6.74 s |
| 缓存开启，上游 2048 分块，稳定运行 | 0 | 4.48 s | 2.97 s | 137 | 7.45 s |
| 缓存开启，512 分块，首次暖缓存复用 | 1536 | 1.01 s | 2.42 s | 113 | 3.43 s |
| 缓存开启，512 分块，后续重复 | 1536 | 0.94 s | 2.26 s | 113 | 3.19 s |

首 token 等待从 4.23 s 降到约 0.94 s，减少约 78%；同一口令总耗时减少约 53%。不同分块下输出 token 数也发生变化，因此总耗时差异包含缓存复用和输出长度差异，不能全部归因于缓存。生成速度仍约 46–50 tok/s，本次优化主要减少重复输入计算。

第一次加载模型及建立缓存仍慢。服务重启后的首次测试墙钟约 22.2 s，其中模型加载约 12.5 s；该请求未计入暖缓存对比。原服务一度暂停，基线第一次请求的客户端墙钟等待也未计入稳定运行对比。

## 真实模型验证

| 输入 | 缓存命中 token | 首 token 等待 | 模型请求总耗时 | 参数核对 |
|---|---:|---:|---:|---|
| 原地起飞 | 1536 | 0.94 s | 3.18 s | 通过 |

测试逐条比较工具调用参数与项目既有样例。区域任务输出较长，因此即使命中缓存，总耗时仍较长。

原始测量记录见 `cache-benchmark-20261014.json`。可在服务运行后重新测试：

```sh
conda activate speech-asr
python -m scripts.benchmark_cache --label warm
```

该脚本只检查模型提出的工具调用，不执行地面站工具；结果默认保存到 `output/cache-benchmark.json`。标签仅用于标记测量，不改变缓存开关。

完整链路复核：真实 oMLX 生成 U 型编队调用，经 L2、MCP、HTTP 在临时模拟地面站成功保存；否定新增 C 型编队的输入没有工具调用。原有 25 项回归测试全部通过。新增测速脚本也实际运行了六条输入，全部参数正确且均命中 1536 token，首 token 等待约 0.90–1.04 s。

服务已用上述适配入口启动并保持监听 `127.0.0.1:18000`，启动输出追加到 `~/.omlx/logs/cache-test-launch.log`，应用结构化日志仍写入 `~/.omlx/logs/server.log`。
