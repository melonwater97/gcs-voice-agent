# 当前接口设计

版本：1.0.0；核验日期：2026-10-16。所有自定义业务接口统一使用 `header + payload`，msg_id 统一为 `MSG-<UUID>`。地面站专用的完整 HTTP 契约见 [地面站对接接口](地面站对接接口.md)。

## 1. 参与方与调用方向

| 参与方 | 地址 / 实现 | 消息端点 |
|---|---|---|
| React 地面站 | web/，127.0.0.1:5173 | FRONT / GS-01 |
| Agent 服务 | agent/，127.0.0.1:18002 | BACKGROUND / AGENT-01 |
| MCP 工具服务 | integrations/mcp_server.py，stdio 子进程 | BACKGROUND / MCP-01 |
| 本地任务模拟 | simulator/backend.py，MCP 进程内 TaskStore | 进程内方法，不是额外服务 |

```text
React 地面站 ── HTTP JSON 信封 ──→ Agent
React 地面站 ←─ HTTP JSON 信封 ─── Agent
                                    │ ↑
                          MCP stdio 中的业务 JSON 信封
                                    ↓ │
                               MCP 工具服务
                                    │
                          本地 TaskStore 创建/保存/模拟执行
```

React 就是地面站，没有独立的地面站业务后端。Vite 托管前端资源，将 /api/* 和 /health 直接代理到 Agent。MCP 不向浏览器发送 HTTP 请求，任务结果随 Agent 本次语音或文本响应返回界面。无需 18001 端口、/tasks 接口或地面站回调。

## 2. 公共信封与协议边界

信封模型 `shared/contracts.py: Message[PayloadT]`，header 模型 MessageHeader，消息由 shared/messages.py 生成。两层固定为 header 和 payload，均为必填；不允许其他顶层字段。

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000007",
    "msg_type": "HEALTH_QUERY",
    "version": "1.0.0",
    "src": {
      "type": "FRONT",
      "id": "GS-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    }
  },
  "payload": {}
}
```

| header 字段 | 规则 |
|---|---|
| msg_id | MSG- 加标准小写 UUID，含连字符；生成器使用 UUID v4 |
| msg_type | 当前动作的消息类型，见下表和各阶段 |
| version | 固定 1.0.0 |
| src / dst | {type, id}；type 为 FRONT 或 BACKGROUND，id 为 1–64 字符 |

msg_id 正则为 `^MSG-[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`。Python 使用 uuid4，React 使用 crypto.randomUUID；没有日期流水号或跨标签页计数器。task_id 仍在创建时生成，继续使用 TASK- 加 32 位 hex。

所有 HTTP 和 MCP 工具业务请求、成功结果及业务错误采用信封。MCP 外层 JSON-RPC、初始化、工具发现以及 SDK 参数校验/协议错误仍使用标准 MCP 协议；LLM 的 OpenAI 兼容调用也遵循模型提供方协议，不改第三方协议。

LLM 只提出业务参数，不生成 header。MCPSession 在发送工具调用前补充消息编号和 Agent → MCP 路由；接收时验证信封、来源/目标和关联编号，再把 payload 交给 Assistant 的业务模型校验。内部 tool_call 事件和历史工具结果用于编排、状态维护与模型上下文，不再通过地面站的操作响应暴露。

## 3. 地面站 → Agent HTTP 接口

/api/voice 与 /api/text 是同一套业务处理的两种输入入口，每轮二选一；/api/text 为可选文字入口，仅接入语音时无需接入它。语音先经 ASR，文字直接进入相同的语义提取和任务操作；澄清补参也可继续用语音，最终 AGENT_OUTPUT 结构一致。

请求均使用 Content-Type: application/json，所有路径使用 POST；语音成功响应使用 application/x-ndjson，其他响应使用 application/json。表中入参由 React 发给 Agent，出参由 Agent 返回 React；入参和出参是信封的 payload。

| 路径 | 请求 msg_type | 入参 payload | 成功 msg_type | 出参 payload |
|---|---|---|---|---|
| /api/voice | VOICE_INPUT | {audio_format: "wav", audio_base64: "…"} | ASR_OUTPUT → AGENT_OUTPUT | 先转写 text，后本次结果 |
| /api/text | AGENT_INPUT | {text} | AGENT_OUTPUT | 本次澄清、成功或错误 |
| /api/record/start | RECORD_START | {} | RECORD_START_OUTPUT | {listening, level, seconds, max_seconds} |
| /api/record/status | RECORD_STATUS | {} | RECORD_STATUS_OUTPUT | {listening, level, seconds, max_seconds} |
| /api/record/stop | RECORD_STOP | {} | ASR_OUTPUT → AGENT_OUTPUT | 先转写 text，后本次结果 |
| /api/state | STATE_QUERY | {} | STATE_OUTPUT | {session_id, revision, tasks, last_task, pending, changes} |
| /health | HEALTH_QUERY | {} | HEALTH_OUTPUT | {status: "ok", service: "agent-web", asr_ready} |

header.src 为 FRONT / 地面站编号，header.dst 固定 BACKGROUND / AGENT-01。Agent 响应 src 为自己，dst 为原 src；请求与响应的对应关系由 HTTP 请求/响应本身确定，信封不再放关联编号。

语音 payload 使用完整 WAV 的标准 Base64，不带 Data URL 前缀或空白。解码后必须是 16 kHz、单声道、PCM16 WAV，最大 8 MiB；含信封的 JSON 上限为 11,250,348 字节。其他请求 JSON 上限为 64 KiB。/api/voice 成功响应采用 application/x-ndjson：ASR 完成立即发送 ASR_OUTPUT，payload 为 {text}，并刷新连接；Agent 同时继续内部语义提取，处理完成再发送 AGENT_OUTPUT 并结束响应。每条消息仍为 header + payload JSON，在传输时压缩为一行并以换行分隔；两条响应均对应同一次最初语音请求，对应关系由该响应本身确定，msg_id 各自唯一。前端逐行读取，先展示转写再展示结果，不回传识别文本；/api/text 仅用于手动文字输入，继续返回普通 application/json。

/api/record/start、/api/record/status、/api/record/stop 是 /api/voice 的服务端录音入口：麦克风由 Agent 的 inputs/recorder.py 采集（16 kHz 单声道 float32），start 打开设备并返回 {listening, level, seconds, max_seconds}，status 返回同一结构的实时快照，stop 复用 /api/voice 的转写与后续处理，同样以 application/x-ndjson 先回 ASR_OUTPUT 再回 AGENT_OUTPUT。录音按 `record:<src>:<msg_id>` 前缀去重，重放只返回缓存。达到 max_seconds（默认 90）时服务端自动停止监听。

AGENT_OUTPUT.payload 只返回一个本次结果：{type: "task_result", tool, task_id, status, task}、{type: "clarify", text} 或 {type: "error", text, tool?}。语音转写通过独立的 ASR_OUTPUT 先行返回，最终结果不重复携带转写。不返回 events、工具调用参数、完整 state、changes 或本机 file；状态和变化只通过 /api/state 查询。HTTP 200 也可能是 type=error 的业务失败；语音流开始后的服务异常/超时通过流内 ERROR 信封返回，客户端也要检查是否已收到终止结果。原裸 JSON、X-Msg-Id、原始 WAV 请求和 GET 查询已停止使用，GET 返回 405；不会同时兼容两套格式。

## 4. 阶段一：创建草稿

### 4.1 Agent → MCP：create_task 入参

发送方：Agent MCP 客户端；接收方：MCP create_task。以下为工具 arguments 的完整内容，不含标准 MCP JSON-RPC 外层。payload 模型是 CreateTaskPayload。

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000010",
    "msg_type": "CREATE_TASK",
    "version": "1.0.0",
    "src": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "MCP-01"
    }
  },
  "payload": {
    "action": "create_task",
    "task": {
      "task_type": "放飞前出任务",
      "task_name": "晨曦",
      "parameters": {
        "mode": "原地起飞",
        "takeoff_altitude": 50.0
      }
    }
  }
}
```

缺少模式、高度或编队参数时，Agent 先向界面澄清，不调用工具。CreateTaskArguments 是 LLM 提案校验模型，只含 payload；完整传输结构是 Message[CreateTaskPayload]。

### 4.2 MCP → Agent：create_task 成功出参

返回方：MCP；接收方：Agent；payload 模型 DraftTaskResult。

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000011",
    "msg_type": "TASK_RESULT",
    "version": "1.0.0",
    "src": {
      "type": "BACKGROUND",
      "id": "MCP-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    }
  },
  "payload": {
    "status": "draft",
    "task_id": "TASK-0123456789abcdef0123456789abcdef",
    "task": {
      "task_type": "放飞前出任务",
      "task_name": "晨曦",
      "parameters": {
        "mode": "原地起飞",
        "takeoff_altitude": 50.0
      }
    }
  }
}
```

MCP 在创建时立即生成 task_id，补全缺省名称并保存到 TaskStore，状态 draft。不保存上传文件、不上传、不执行。编号经 MCP → Agent → React 返回，不由地面站生成或回传。

### 4.3 Agent → React：创建展示

原语音或文本请求返回 AGENT_OUTPUT，payload 为 {type: "task_result", tool: "create_task", task_id, status: "draft", task}。只携带本次任务的一份完整参数。Agent 内部记录创建变化，界面另查 /api/state 同步列表；不回传 MCP 的传输 header 或调用参数。

## 5. 阶段二：保存并模拟上传

### 5.1 Agent → MCP：upload_task 入参

发送方：Agent；接收方：MCP upload_task；payload 模型 TaskIdPayload。

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000012",
    "msg_type": "UPLOAD_TASK",
    "version": "1.0.0",
    "src": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "MCP-01"
    }
  },
  "payload": {
    "task_id": "TASK-0123456789abcdef0123456789abcdef"
  }
}
```

只引用创建时的编号。UploadTaskArguments 是内部提案校验模型 {task_id}，MCPSession 将其装入信封 payload。

### 5.2 MCP → Agent：upload_task 成功出参

返回方：MCP；接收方：Agent；payload 模型 UploadTaskResult。

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000013",
    "msg_type": "TASK_RESULT",
    "version": "1.0.0",
    "src": {
      "type": "BACKGROUND",
      "id": "MCP-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    }
  },
  "payload": {
    "status": "uploaded",
    "task_id": "TASK-0123456789abcdef0123456789abcdef",
    "task": {
      "task_type": "放飞前出任务",
      "task_name": "晨曦",
      "parameters": {
        "mode": "原地起飞",
        "takeoff_altitude": 50.0
      }
    },
    "file": "/绝对路径/output/TASK-0123456789abcdef0123456789abcdef.json"
  }
}
```

只接受本会话 draft 任务。TaskStore 将 UploadTaskResult 的业务数据保存为 UTF-8 JSON，成功后转 uploaded；文件内容等于此信封的 payload，是本地记录，不是另一次接口消息。写入失败保留 draft，同名文件存在时报错，不覆盖。file 是 Agent 本机路径，不是浏览器下载 URL。

“上传”是当前模拟业务阶段，没有 MCP → 地面站 HTTP 请求或地面站 → MCP 回执。

### 5.3 Agent → React：上传展示

Agent 返回 AGENT_OUTPUT，payload 为 {type: "task_result", tool: "upload_task", task_id, status: "uploaded", task}。不向界面返回本机 file 路径或 MCP 调用参数；界面随后查询 /api/state 同步。

返回方：MCP；接收方：Agent；payload 模型 ExecuteTaskResult。


### 6.3 Agent → React：执行展示

原语音或文本请求返回 AGENT_OUTPUT，payload 为 {type: "task_result", tool: "execute_task", task_id, status: "executing", task}。MCP 执行回执只含编号和状态，Agent 从本次会话补入完整 task，使三个阶段对外字段一致；完整状态另查 /api/state。

## 7. 错误、状态和重试

MCP 业务失败返回 ERROR 信封，Agent 将 payload.error 转为对外 AGENT_OUTPUT 的 {type: "error", text, tool?}，失败不返回成功任务结果。示例：

```json
{
  "header": {
    "msg_id": "MSG-550e8400-e29b-41d4-a716-000000000016",
    "msg_type": "ERROR",
    "version": "1.0.0",
    "src": {
      "type": "BACKGROUND",
      "id": "MCP-01"
    },
    "dst": {
      "type": "BACKGROUND",
      "id": "AGENT-01"
    }
  },
  "payload": {
    "error": "任务当前状态为 draft，不能转到 executing，请按 创建→上传→执行 顺序操作"
  }
}
```

MCP 的参数模型校验或协议失败由 SDK 的 is_error 表达，Agent 同样转换为 type=error 的本次结果。HTTP 参数、消息头、路由、长度错误为 400，媒体类型错误 415，音频或空转写 422，ASR/I/O 错误 500，超时 504；这些 HTTP 响应也都使用 ERROR 信封。详细错误契约见地面站对接文档。

状态严格按 draft → uploaded → executing。completed、aborted 只预留，没有对应工具。未知编号、重复上传、跳步执行、重复执行均拒绝。

Agent 快照含单调递增 revision、完整任务、last_task、pending 和最近 100 条 changes；变化记录含 before/after、UTC 时间和触发请求的 MSG-UUID。重启清空会话，文件不自动恢复。同一会话任务目录跨对话窗口保留，多个页面共享状态。

A1/A2 按端点 + src.id + msg_id 缓存最近共 256 个响应。重试保留完整信封，新口令/录音用新 UUID。Agent 超时 180 秒、界面等待 190 秒；超时不取消已开始操作，先查状态再用原信封重试。重启或缓存淘汰后不保证旧请求去重。

## 8. 参数和运行配置

任务类型当前为 放飞前出任务。原地起飞必填 takeoff_altitude（>0 m）；在指定位置展开还需 formation：C型必填 open_angle（0<角度≤360度）、radius（>0 m）、position；U型必填 formation_length、formation_width（均>0 m）、position。position 是 WGS84 {longitude, latitude}，范围经度 [-180,180]、纬度 [-90,90]，拒绝无穷和 NaN。名称长度 1–64，默认“任务类型-编号前8位hex”，名称不作唯一键，重名选择需澄清。

```sh
# Agent 加载 ASR、模型客户端，并自动启动 MCP
python main.py web --task-output-dir /绝对路径/任务目录

# React 地面站：另一终端
cd web
npm run dev
```

输出目录默认 output/，通过 TASK_OUTPUT_DIR 传给 MCP 子进程。文本 CLI 也支持 --task-output-dir；mcp 子命令仅用于单独启动 stdio 服务。

ASR 默认 SeACo-Paraformer，加载 config/asr_hotwords.txt 的 22 个领域词，并向后续录音加入已创建任务名称；可通过 --asr-hotwords-file 修改词表。首次命名仍依赖模型识别，热词不保证消除同音字错误。

扩展需更新 shared/contracts.py 的 TASK_TYPES / LAUNCH_MODES / FORMATION_TYPES、MSG_TYPES、提示词和测试；新增工具还需登记 assistant/tools.py 的参数/结果校验和 MCP 的业务信封映射。根目录 接口.json 是历史协议示例，当前运行不读取它。
